# ADR 0001: uv como gerenciador de pacotes e ambientes

- **Status:** aceito
- **Data:** 2026-10-13

## Contexto

O projeto precisa de ambientes reprodutíveis no Mac (desenvolvimento, com GPU via MPS), no CI
(Linux) e em imagens Docker (Linux, só CPU). O PyTorch complica: o wheel padrão de Linux traz
CUDA (vários GB), e o build CPU-only fica num índice separado.

## Decisão

Usar o **uv** para venv, resolução, lockfile e execução de comandos, com:
- um `uv.lock` universal versionado no git;
- o índice `pytorch-cpu` declarado com `explicit = true` e aplicado ao `torch` só em
  `sys_platform == 'linux'`;
- grupos de dependências (`dev`, `train`) em vez de vários `requirements*.txt`.

## Alternativas consideradas

- **pip + requirements.txt (pip-tools):** sem lock multiplataforma nativo, e o índice do
  PyTorch por plataforma exige arquivos separados.
- **Poetry:** tem lock, mas a resolução é mais lenta e o suporte a índices por plataforma e
  marker é mais trabalhoso.
- **conda:** resolveria o CUDA/CPU, mas pesa nas imagens e foge do padrão PyPI.

## Consequências

- (+) O mesmo lock gera ambientes idênticos no Mac, no CI e no Docker, e instala em segundos.
- (+) Imagens Linux sem CUDA.
- (−) Quem contribuir precisa instalar o uv (`brew install uv`).
- (−) O lock fica maior por conter wheels de várias plataformas.
